## Required in the submission
- [ ] **Public GitHub repo** (GitLab and Bitbucket are not accepted): https://github.com/Utsav-Singh-35/ghostlight-isles
- [ ] **Open-source license** that shows in the repo's About section (MIT, in `LICENSE`)
- [ ] **`/.kiro` folder at the repo root**, with specs, hooks and steering. Never add it to `.gitignore`; that can disqualify the entry.
- [ ] **Everything needed to run the project** in the repo: source, assets and instructions (README)
- [ ] **Working app URL.** If login is needed, give judges test credentials and steps in the private field of the form. We use guest login, so none are needed.
- [ ] **Text description** of the features
- [ ] **Demo video under 3 minutes** on YouTube, showing the game running on the device it was built on. Judges may stop watching at 3 minutes. No third-party trademarks or copyrighted music without permission.
- [ ] **"How I used Kiro" write-up** (draft it from `kiro-usage-log.md`)
- [ ] **Category:** Costume Contest (one category per project)
- [ ] Declare any code that existed before Oct 30 other than frameworks, libraries and starter templates. We have none.
- [ ] Everything in English

### Questions the "How I used Kiro" write-up should answer
- Which Kiro surfaces we used (IDE, CLI, Web, Crew), and how they differed
- Custom agents: did we build or use any, and how did they help
- Agent hooks: what they automated and how that improved the workflow
- Spec-driven development: how we structured specs, and how it compared to vibe coding
- Steering: how it improved Kiro's answers, and which approach worked best
- MCP: how it extended Kiro, and what would have been hard without it
- Property-based testing: what it caught that unit tests might have missed, and for which requirements
- Kiro powers: which ones, and which tools we would not have used without them

## Judging (two stages)
1. Pass or fail: fits the theme and uses Kiro. Judges can disqualify entries that use Kiro too little.
2. Five criteria, each scored out of 10 and weighted 20%:
   - **Potential Impact:** solves a real problem for real users, useful, easy to understand, likely to be used
   - **Technological Implementation:** depth and quality of Kiro use, deliberate choices about AI-assisted development
   - **Design:** a finished product rather than a tech demo, clear and polished
   - **Innovation/Idea:** original, different from what exists
   - **Presentation:** the video shows the project working end to end and makes clear what problem it solves, for whom and why
